## User Story

As a Compliance operator, I want an end-to-end POC that simulates AML failure and routes cases to the underwriter queue with explainability artifacts, so that we can validate routing and case handling.

This story implements FR-013: WHEN identity verification is required, THE SYSTEM SHALL verify NI number, name, and date of birth via HMRC identity verification API.

## Business Context

Demonstrate AML failure path: generate synthetic application, run AML screening, create compliance case, and surface in underwriter queue with explainability artifacts.

This story implements KYC identity verification (FR-013): perform HMRC identity checks using the HMRC identity verification API, validate identity attributes, attach verification result (pass/fail) to the application enrichment payload, and surface verification evidence in the compliance case. Store KYC verification details as a structured record to satisfy audit requirements.

FR-013 canonical requirement (verbatim): The system shall perform KYC identity verification by cross-referencing the applicant's NI number, name, and date of birth against the HMRC identity verification API.

This story ensures KYC identity verification via HMRC is executed as part of the enrichment step prior to AML screening and offer generation; verification must include the applicant's NI number, name, and date of birth and produce a structured `kyc_result` attached to the application enrichment payload.
