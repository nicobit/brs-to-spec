# S-003.1 - AML orchestration connector

| Field | Value |
|---|---|
| Story ID | S-003.1 |
| Title | AML orchestration connector |
| Layers | backend / integration |
| Story Type | feature |

## User Story

As an integration engineer, I want an AML orchestration connector that invokes third-party verifiers and returns structured screening results.

## Business Context

Provide a pluggable connector to integrate with AML providers and return structured results to the orchestration engine.

## Linked Requirements

| ID | Requirement |
|---|---|
| FR-012 | AML screening before offer generation |

## Requirements Implemented

- FR-012


## In Scope

- Invoke third-party AML providers and normalize their responses for orchestration.

## Implementation Guidance

- Implement a connector that supports pluggable providers. Normalize responses to the orchestration schema and handle retry/backoff.

## Acceptance Criteria

### AC-001 — Provider invocation `[integration]` `[critical]` `[automate]`

```gherkin
Scenario: AML connector returns structured screening result
  Given a submission requiring AML screening
  When the connector invokes the provider
  Then it returns a structured screening result usable by orchestration
```

### AC-002 — Provider failure handling `[integration]` `[important]` `[automate]`

```gherkin
Scenario: Provider failure handled gracefully
  Given the provider responds with an error
  When the connector processes the response
  Then it returns a normalized error result and triggers retry/backoff per policy
```

### AC-003 — Authentication and rate limit boundary `[integration]` `[standard]` `[automate]`

```gherkin
Scenario: Connector enforces provider auth and respects rate limits
  Given the connector has provider credentials
  When invoking the provider at scale
  Then it authenticates and enforces client-side rate limits and backoff
```

### AC-004 — Response normalization `[integration]` `[important]` `[automate]`

```gherkin
Scenario: Normalize provider response to orchestration schema
  Given a provider-specific screening response
  When the connector normalizes the result
  Then the orchestration engine receives a canonical screening result schema
```

FR-012 canonical requirement: The system shall perform AML screening before offer generation.

This connector is invoked as part of the pre-offer pipeline; screening results marked `COMPLIANCE_HOLD` will block offer generation until manual review completes or automated remediation rules apply.
