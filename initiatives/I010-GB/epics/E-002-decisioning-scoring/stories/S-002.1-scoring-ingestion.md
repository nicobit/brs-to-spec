# S-002.1 - Scoring ingestion API

| Field | Value |
|---|---|
| Story ID | S-002.1 |
| Title | Scoring ingestion API |
| Layers | backend / infrastructure |
| Story Type | feature |

## User Story

As a backend engineer, I want the Intake API to publish normalized scoring job events so that the scoring pipeline can reliably consume them.

## Business Context

Provide a stable ingestion contract for scoring jobs, including enrichment and normalization of submission payloads.

## In Scope

- Implement API contract for normalized scoring job events and a retry/dead-letter behavior for failed publishing.

## Implementation Guidance

- Use the existing Intake API to emit `application.scoring.job` events with normalized payload fields. Ensure schema versioning and clear enrichment steps are included.

## Acceptance Criteria

### AC-001 — Publish normalized event `[api]` `[critical]` `[automate]`

```gherkin
Scenario: Intake API publishes normalized scoring job event (happy path)
  Given a valid application submission
  When the submission is accepted
  Then the Intake API publishes an `application.scoring.job` event containing normalized fields required by scoring pipeline
```

### AC-002 — Reject invalid submissions `[api]` `[important]` `[automate]`

```gherkin
Scenario: Invalid submission leads to validation failure
  Given an invalid application submission
  When the Intake API receives the submission
  Then the submission is rejected and no scoring.job event is published
```

### AC-003 — Retry and dead-lettering `[integration]` `[important]` `[automate]`

```gherkin
Scenario: Transient publish failure is retried and dead-lettered
  Given the event bus experiences transient failures
  When the Intake API publishes the scoring.job event
  Then the publisher retries according to policy and eventually moves the message to dead-letter on persistent failure
```

### AC-004 — Boundary payload handling `[integration]` `[standard]` `[automate]`

```gherkin
Scenario: Boundary payload accepted within schema limits
  Given a submission at the maximum allowed payload size
  When the Intake API accepts the submission
  Then a normalized scoring.job event is published without truncation
```
