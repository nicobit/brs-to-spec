# S-004.0 - Offer generation end-to-end

| Field | Value |
|---|---|
| Story ID | S-004.0 |
| Title | Offer generation end-to-end |
| Layers | backend / integration |
| Story Type | spike |

## Business Context

POC to validate offer generation, presentation in portal and email, and persistence of the offer document for audit.

## User Story

As a system, when an application is approved, we want to generate an offer and present it to the applicant so that they can accept digitally.

## Requirements Implemented

- FR-020, FR-021

## Acceptance Criteria

- Offer document is created with required fields and persisted.
- Offer visible in portal and sent via email.

## Gherkin Acceptance Criteria

```gherkin

@important @automate
Feature: Offer generation acceptance criteria

@important @automate
Scenario: Offer generation - happy path
	Given an approved application with ARN "A1"
	When the system generates an offer
	Then a new OfferDocument is persisted and a 201 response is returned

@important @automate
Scenario: Offer generation - validation failure
	Given an application missing required fields
	When the system attempts to generate an offer
	Then a 400 error is returned

@important @automate
Scenario: Offer generation - boundary
	Given applicant requests maximum allowed amount
	When the system generates an offer
	Then calculation handles maximum without overflow

@important @automate
Scenario: Offer generation - integration failure
	Given the email subsystem is unavailable
	When the system generates an offer
	Then the offer is persisted and email is queued for retry
```
