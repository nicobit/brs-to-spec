## Business Context

Send disbursement instructions to Temenos T24 with required fields and ensure idempotent retries and confirmation handling.

## User Story

As the system, when disbursement is authorised, I want to send an instruction to T24 and record confirmation so funds are moved reliably.

## Requirements Implemented

- FR-024, FR-025, FR-026

## Acceptance Criteria

- Instruction sent with expected fields; retries and confirmation handling implemented.

## Gherkin Acceptance Criteria

```gherkin
@critical @automate
Feature: Disbursement orchestration acceptance criteria

@critical @automate
Scenario: Disbursement instruction - happy path
	Given cooling-off expired for an accepted offer
	When the system sends a disbursement instruction
	Then T24 returns confirmation and the system records success

@important @automate
Scenario: Disbursement instruction - retry on failure
	Given T24 is temporarily unavailable
	When the system sends an instruction
	Then the system retries according to backoff and eventually succeeds or records failure

@important @automate
Scenario: Disbursement instruction - idempotency
	Given duplicate instruction attempts
	When the system retries
	Then T24 processes instruction only once and system records idempotent result

@important @automate-later
Scenario: Disbursement instruction - malformed request
	Given invalid fields in instruction
	When sending to T24
	Then the system validates and does not send malformed requests
```

## Implementation Guidance

Refer to `implementation-contract.md` for the API contract; orchestration must ensure idempotency and retries when communicating with T24.
