# S-004.1 - Digital acceptance via DocuSign

| Field | Value |
|---|---|
| Story ID | S-004.1 |
| Title | Digital acceptance via DocuSign |
| Layers | frontend / backend / integration |
| Story Type | feature |

## Business Context

Capture applicant acceptance via DocuSign and persist evidence (timestamp, signer, IP) for audit and cooling-off enforcement.

## User Story

As an applicant, I want to sign the offer digitally so that my acceptance is recorded and processed.

## Requirements Implemented

- FR-022, FR-023

## Acceptance Criteria

- DocuSign callback records acceptance and triggers cooling-off schedule.

[critical] [automate]

## Implementation Guidance

Implement webhook verification and idempotent recording in `AcceptanceRecord`.

## Requirements Referenced

- FR-022
- FR-023

## In Scope

- Verify DocuSign callback authenticity
- Persist AcceptanceRecord with timestamp and signer IP

## Test Expectations

- Unit tests for webhook handling
- Contract tests for `/api/offers/{offer_id}/accept`
- Integration tests with DocuSign adapter

## Dependency Contracts

- Consumes: `POST /api/offers/{offer_id}/accept` (acceptance callback)

## Required Tests

- Unit: webhook signature verification
- Integration: callback processing and idempotency

## Gherkin Acceptance Criteria

```gherkin
@critical @automate
Feature: Digital acceptance acceptance criteria

@critical @automate
Scenario: Acceptance recorded - happy path
	Given an offer exists with id "O1"
	When DocuSign posts an acceptance callback
	Then AcceptanceRecord is created with signed_at and signer recorded

@important @automate
Scenario: Acceptance callback - invalid signature
	Given an offer exists
	When DocuSign posts a callback with invalid signature
	Then the callback is rejected with 401

@important @automate
Scenario: Acceptance callback - duplicate
	Given an acceptance already recorded
	When a duplicate callback arrives
	Then the system ignores duplicate and returns 200

@important @automate-later
Scenario: Acceptance callback - missing fields
	Given a callback missing required fields
	When the callback is processed
	Then a 400 response is returned and no AcceptanceRecord is created
```
