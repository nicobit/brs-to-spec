# S-001.4 - Status lookup API

## Metadata

| Field | Value |
|---|---|
| Story ID | S-001.4 |
| Title | Status lookup API |
| Layers | backend |
| Story Type | backend-endpoint |

## User Story

As an applicant, I want to lookup status by ARN and DOB so that I can see my application's progress without registering.

## Business Context

Expose GET /api/intake/status to return current application status by ARN+DOB with appropriate PII protections.

## Linked Requirements

| Requirement | Title |
|---|---|
| FR-005 | Retrieve status by ARN and DOB |

## Requirements Implemented

- FR-005

## Requirements Referenced

- NFR-004 (PII encryption)

## In Scope

- GET /api/intake/status query by arn and dob, return status and last_update.

## Implementation Guidance

Use implementation contract response schema. Ensure DOB+ARN lookup is rate-limited and logs to audit store.

## Dependency Contracts

- Intake API database

## Acceptance Criteria

### [backend] [critical] [automate]
```gherkin
Scenario: Valid lookup returns status
  Given an existing application with arn "EXAMPLE-ARN" and dob "1990-01-01"
  When GET /api/intake/status?arn=EXAMPLE-ARN&dob=1990-01-01
  Then respond 200 with JSON containing arn and status
```

### [backend] [important] [automate]
```gherkin
Scenario: Unknown ARN returns 404
  Given no application exists for arn "MISSING-ARN"
  When GET /api/intake/status?arn=MISSING-ARN&dob=1990-01-01
  Then respond 404
```

### [integration] [standard] [automate]
```gherkin
Scenario: Lookup enforces PII protection
  Given a request for status
  When the request is processed
  Then PII fields are returned only as permitted and transit encrypted
```

### [integration] [edge] [automate]
```gherkin
Scenario: Invalid DOB format returns 400
  Given a request with dob = "not-a-date"
  When GET /api/intake/status?arn=EXAMPLE-ARN&dob=not-a-date
  Then respond 400 with validation error for dob
```
