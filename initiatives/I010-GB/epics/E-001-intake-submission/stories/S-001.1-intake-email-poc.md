# S-001.1 - Intake: confirmation-email POC

| Field | Value |
|---|---|
| Story ID | S-001.1 |
| Title | Intake: confirmation-email POC |
| Layers | backend / integration |
| Story Type | backend-endpoint |

## Business Context

Validate that upon `application.submitted` the confirmation email is queued and delivered using the mock email provider, and that message contents meet business rules.

## User Story

As an operator, I want confirmation emails to be reliably queued and sent so applicants receive timely notifications.

## Linked Requirements

| Requirement | Title |
|---|---|
| FR-004 | Email confirmation within 2 minutes |
| FR-027 | Applicant notification on disbursement |

## Requirements Implemented

- FR-004

## Requirements Referenced

- NFR-004 (PII encryption)

## In Scope

- Consuming `application.submitted` events
- Queueing and sending confirmation emails via mock provider
- Email content validation (contains arn and decision timeline)

## Implementation Guidance

Listen to `application.submitted` from the audit store; transform to email payload and enqueue to the mock provider. Use templating guidelines from `implementation-contract.md`.

## Acceptance Criteria

### [integration] [critical] [automate]
```gherkin
Scenario: Confirmation email is queued and sent
	Given an application.submitted event with valid arn
	When the email worker processes the event
	Then an email is enqueued to the mock provider containing the arn and applicant email
```

### [integration] [important] [automate]
```gherkin
Scenario: Email content includes required fields
	Given an email was enqueued
	When the mock provider receives the request
	Then the payload contains arn, applicant_id and a human-readable decision timeline
```

### [integration] [standard] [automate]
```gherkin
Scenario: Retry on transient send failures
	Given the mock provider returns 5xx on first attempt
	When the worker retries
	Then the email is delivered on a subsequent attempt and logged
```

### [integration] [standard] [automate]
```gherkin
Scenario: Do not send email for opted-out applicants
	Given an applicant has opted out of emails
	When an application.submitted event is processed
	Then no email is enqueued for that applicant
```
