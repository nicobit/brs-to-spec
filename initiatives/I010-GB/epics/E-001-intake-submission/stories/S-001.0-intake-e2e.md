# S-001.0 - Intake: end-to-end POC

| Field | Value |
|---|---|
| Story ID | S-001.0 |
| Title | Intake: submission + ARN POC |
| Layers | backend |
| Story Type | spike |

## Business Context

A focused proof-of-concept to validate the Intake submission path, ARN generation, and event publication using mock adapters. Email confirmation and downstream consumers are handled in a separate follow-on spike.

## User Story

As a delivery team, we want an end-to-end POC so that we can validate integration points and observability before detailed story work.

## Linked Requirements

| Requirement | Title |
|---|---|
| FR-001 | Loan application submission |

## Requirements Implemented

- FR-001

## Requirements Referenced

- NFR-004 (PII encryption), NFR-001 (Form load time)

## In Scope

- Submission handling and ARN generation
- Publishing `application.submitted` event to the audit store
- Verifying event is produced (mock consumer)

## Implementation Guidance

Refer to `implementation-contract.md` for API paths (`POST /api/intake/submit`, `GET /api/intake/status`) and event payloads. Use mock adapters configured in CI for scoring and email.

## Dependency Contracts

- Intake API (`POST /api/intake/submit`, `GET /api/intake/status`)
- Scoring pipeline consumer (mock)
- Email provider (mock)

## UI Behaviour

POC exercises the form submission only; status lookup and UI pages are out-of-scope for this spike.

## Acceptance Criteria

- POC can submit an application and receive ARN.
- Application.submitted event is published to the audit store and consumed by scoring mock.
- Confirmation email flow works end-to-end with test provider.

### [integration] [critical] [automate]
```gherkin
Scenario: Successful application submission returns ARN
	Given the applicant completes the application form with valid values
	When they submit the form to POST /api/intake/submit
	Then the API responds 201 with JSON containing an "arn"
	And the response body contains a syntactically-valid arn
```

### [integration] [important] [automate]
```gherkin
Scenario: Submission validation rejects invalid loan amount
	Given the applicant submits loan_amount = 999 (below minimum)
	When they POST to /api/intake/submit
	Then the API responds 400 with validation error for loan_amount
```

### [integration] [standard] [automate]
```gherkin
Scenario: Event publication observed by mock consumer
	Given a successful submission that returned an arn
	When the system publishes an "application.submitted" event
	Then the mock consumer receives the event within 10s and the payload contains arn and applicant_id
```

### [integration] [standard] [automate]
```gherkin
Scenario: Event contains required trace fields
	Given a successful submission
	When the application.submitted event is emitted
	Then the event payload contains fields: arn, applicant_id, submitted_at
```
