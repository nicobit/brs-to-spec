## User Story

As an Applicant, I want to submit my application with required identity and contact details so that the application can be processed and scored.

---

## Business Context

This story delivers the primary data capture surface for applicant onboarding; accurate capture reduces processing errors downstream and improves time-to-decision.

- **API:** `POST /api/v1/applications`
- **Events:** publish `application.submitted` on success

---

## Acceptance Criteria

### AC-001 — Successful submission `[integration]`

```gherkin
Scenario: Applicant submits a valid application
  Given the applicant has completed all required fields
  When they submit the application
  Then the system returns HTTP 201 with an `application_id` and emits `application.submitted`
```

### AC-002 — Validation failures `[unit]`

```gherkin
Scenario: Applicant submits missing required fields
  Given the applicant omits the email
  When they submit
  Then the system returns HTTP 400 with field-level errors
```

### AC-003 — ARN status retrieval `[api]`

```gherkin
Scenario: Applicant retrieves status by ARN
  Given an applicant has received an ARN after submission
  When they call GET /api/v1/applications/{arn}/status with ARN and DOB
  Then the system returns the current status for that ARN without requiring registration
```
