## User Story

As Operations, I want task assignment and SLA monitoring so that tasks are retriable and SLA breaches trigger alerts or escalations.

---

## Business Context

SLAs ensure timely handling of referred applications and provide triggers for escalation if response times exceed thresholds.

---

## Linked Requirements

| ID | Requirement |
|---|---|
| FR-015 | Task assignment and routing |
| FR-016 | SLA monitoring and alerts |

---

## Implementation Guidance

- Tasks have `created_at` and `updated_at` and SLA timers driven by timestamp + priority.
- SLA breach produces `audit.event` and creates an escalation task if not resolved within threshold.

---

## Acceptance Criteria

### AC-001 — SLA breach `[integration]`
```gherkin
Scenario: SLA breach creates escalation
  Given a task created with priority HIGH and SLA 4 hours
  When no action occurs before SLA expiry
  Then an escalation task is created and `audit.event` emitted
```

### AC-002 — Assignment validation `[unit]`
```gherkin
Scenario: Invalid assignment rejected
  Given a task exists in state NEW
  When an assignment request is made with an invalid assignee id
  Then the API returns 400 and the task remains in state NEW
```
