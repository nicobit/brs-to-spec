## User Story

As Platform, I want audit events retained and archived per regulatory policy so that compliance evidence is preserved and retrievable.

---

## Business Context

Regulatory retention requirements mandate long-term storage and verifiable archival for audit events tied to compliance decisions.

---

## Linked Requirements

| ID | Requirement |
|---|---|
| FR-019 | Retention and archival requirements |
| FR-028 | Audit retrieval and searchability |
| FR-030 | Proof of custody and tamper evidence |

---

## Implementation Guidance

- Store canonical `AUDIT_EVENTS` in an immutable store with 7-year retention. Implement indexing for retrieval by arn and correlation_id.

---

## Acceptance Criteria

### AC-001 — Store and retrieve `[e2e]`
```gherkin
Scenario: Store and retrieve audit event
  Given an `audit.event` emitted for arn "ARN-123"
  When a retrieval API is called with correlation_id
  Then the event is returned and metadata shows storage timestamp and custody hash
```

### AC-002 — Archival failure handling `[integration]`
```gherkin
Scenario: Archival job fails due to storage error
  Given archival job attempts to move old events to cold storage and storage service returns error
  When the job runs
  Then events remain flagged for retry and an `audit.event` with error details is emitted
```
