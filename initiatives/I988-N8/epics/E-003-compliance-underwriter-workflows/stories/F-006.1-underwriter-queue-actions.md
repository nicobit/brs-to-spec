## User Story

As an Underwriter, I want a task queue where I can claim, review, and action referred applications so that decisions are auditable and timely.

---

## Business Context

Underwriters need a clear, auditable workflow to review flagged applications and make business decisions. This story creates the task API and basic UI wiring for assignment and actions.

## Implementation Guidance

- **Entity:** `UNDERWRITER_TASKS`
- **API:** `GET /api/v1/underwriter/tasks`, `POST /api/v1/underwriter/tasks/{id}/actions`
- **Status:** tasks lifecycle: NEW -> ASSIGNED -> IN_PROGRESS -> APPROVED/REFERRED/ESCALATED
- **Events:** emits `task.actioned` and `audit.event`

---

## Acceptance Criteria

### AC-001 — Claim and action task `[api]`
```gherkin
Scenario: Underwriter claims and approves a task
  Given a task exists in state NEW for arn "ARN-XYZ12345"
  When underwriter "uw-1" posts action approve with a note
  Then task state becomes APPROVED and `task.actioned` is emitted with actor and note
```

### AC-002 — Audit history persisted `[unit]`
```gherkin
Scenario: Action history records actor and timestamp
  Given a task with id "T-1"
  When two actions are performed by different actors
  Then `UNDERWRITER_TASKS.actions_history` contains both entries with actor and timestamp
```

### AC-003 — Escalation path `[integration]`
```gherkin
Scenario: Underwriter escalates high-risk task
  Given a task marked HIGH priority
  When underwriter escalates
  Then an escalation task is created and `audit.event` records escalation destination
```
