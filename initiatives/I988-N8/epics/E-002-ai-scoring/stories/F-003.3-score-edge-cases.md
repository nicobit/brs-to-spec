## User Story

As a **scoring service**, I handle edge cases (missing data, external adapter failures) so that scoring remains robust and auditable.

---

## Business Context

Handling edge cases reduces false negatives and ensures downstream services are not blocked by transient failures.

---

## Linked Requirements

- REQ-018, FR-007, FR-008

---

## Implementation Guidance

- Implement retries, fallbacks, and clear telemetry. Provide contract tests for adapter failure modes.

---

## Acceptance Criteria

### AC-001 — Fallback to cached data `[integration]`

```gherkin
Scenario: Adapter fails and fallback used
  Given Experian adapter returns an error
  When scoring runs
  Then the scoring service uses cached or default data and emits a warning
```

### AC-002 — Missing inputs handled `[unit]`

```gherkin
Scenario: Missing optional inputs do not crash scoring
  Given required core fields present but optional fields missing
  When scoring runs
  Then a score is produced with a flag indicating degraded inputs
```

## Test Expectations

| Test Type | What to verify | Why |
|---|---|---|
| integration | adapter failure and fallback behaviour | prevents downstream blocking |
| unit | flag logic for degraded inputs | clarity in audit logs |
