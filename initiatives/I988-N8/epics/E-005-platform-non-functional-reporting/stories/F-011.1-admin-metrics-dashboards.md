## User Story

As SRE, I want dashboards for key metrics (latency, queue depth, reconciliation failures) so we can operate and alert on platform health.

## Acceptance Criteria

### AC-001 — Dashboard availability `[e2e]`
```gherkin
Scenario: Dashboard shows key metrics
  Given metrics are emitted to monitoring
  When SRE opens dashboard
  Then latency, queue depth, and failure rates are visible and filterable by region
```

## Business Context

Operational teams and product owners rely on dashboards to detect regression in platform behaviour and to prioritise remediation.

---

## Implementation Guidance

- Use `GET /api/v1/platform/metrics` as the canonical API for metric retrieval. Ensure metrics include region and service tags.

---

### AC-002 — Metrics ingestion validation `[integration]`
```gherkin
Scenario: Metrics ingestion fails for malformed payload
  Given a malformed metric payload is emitted
  When ingestion service receives it
  Then the payload is rejected and an `audit.event` is recorded
```
