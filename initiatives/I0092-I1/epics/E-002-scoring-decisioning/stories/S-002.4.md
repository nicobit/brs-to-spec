# S-002.4 — Scoring explainability and model traceability (FR-028)

| Layers | backend, infrastructure |

## Business Context

Explainability is required for regulatory review and audit trails for AI decisions.

## User Story

As an auditor, I want to see why a score was produced so that decisions can be explained.

## Implementation Guidance

Persist modelVersion and explainability artifacts alongside ScoreRecord; provide retrieval API.

## Test Expectations

- Integration tests verifying explainability returned for sample cases

## Requirements

- FR-028, REQ-007, REQ-008, REQ-013

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Explainability available
  Given a scored application
  When explainability is requested
  Then explainability data and modelVersion are returned

Scenario: Explainability for historical score
  Given a historical score record
  When explainability retrieval is requested
  Then stored explainability artifacts are returned
```
