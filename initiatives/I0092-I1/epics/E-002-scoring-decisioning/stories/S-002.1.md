
# S-002.1 — Scoring pipeline core (FR-006, FR-007)

| Layers | backend, integration |

## Business Context

Scoring is critical to early decisioning; lightweight pipeline reduces manual review load.

## User Story

As a `system`, I want the scoring pipeline to consume application data and return a reproducible score so that automated decisioning can proceed.

## Implementation Guidance

Reference `implementation-contract.md` in the epic folder. Implement a backend service with a mocked Experian adapter for CI tests.

## Test Expectations

- Unit tests for scoring logic
- Integration tests with mocked Experian responses
- E2E test validating score returned for sample payloads

## Requirements

- FR-006, FR-007

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Happy path - scoring returns a score
	Given a valid application exists
	When the scoring service is invoked with the application
	Then the service returns a numeric score and status 200

Scenario: Experian timeout handled
	Given Experian returns a timeout
	When the scoring service calls Experian
	Then the service retries and returns a controlled failure or fallback score
```
