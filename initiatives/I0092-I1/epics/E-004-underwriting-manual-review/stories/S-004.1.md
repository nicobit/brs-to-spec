
# S-004.1 — Underwriter queue UI

| Layers | frontend, backend |

## Business Context

Underwriters need clear case context and audit trails to make compliant decisions.

## User Story

As an underwriter, I want to view application details and record decisions so that the required audit is captured.

## Implementation Guidance

Follow audit schema in `implementation-contract.md` and ensure immutability for audit store.

## Test Expectations

- UI acceptance tests for action flows
- Integration tests for audit logging

## Requirements

- FR-016, FR-017, FR-018, FR-019

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Underwriter approves application
	Given an application in the underwriter queue
	When the underwriter approves with reason
	Then an audit record is stored with the decision and metadata

Scenario: Underwriter requests more info
	Given an application requiring more info
	When the underwriter requests info
	Then the application is moved back to applicant workflow
```
