
# S-001.1 — Applicant form UI and submission

| Layers | frontend, backend |

## Business Context

Collecting consistent applicant data reduces downstream errors and accelerates processing.

## User Story

As an applicant, I want to enter my application details so that I receive an ARN and confirmation.

## Implementation Guidance

Follow the epic `implementation-contract.md` for API shape; implement client-side validation and clear error messages.

## Test Expectations

- Unit tests for validation logic
- Integration test for form submission and ARN generation

## Requirements

- FR-001, FR-002, FR-003

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Successful submission
	Given the applicant completes required fields
	When they submit the form
	Then they receive an ARN and status 201

Scenario: Validation error
	Given the applicant omits a required field
	When they submit the form
	Then they receive a 400 with validation messages
```
