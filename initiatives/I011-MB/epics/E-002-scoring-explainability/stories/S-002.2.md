## User Story

As the ExplainabilityStore, I want to define and persist explainability traces so that scoring results are auditable and queryable.

## Business Context

Persistent explainability traces are required for regulatory audits and to surface model rationale to underwriters. The store must be tamper-evident and performant for queries by `/scores/{id}` API.

THE SYSTEM SHALL use explainable models for scoring; black-box models without explainability are not permitted.

- `GET /api/v1/explainability/{id}` — retrieve explainability trace by id

## Acceptance Criteria

AC Tags: [important] [automate]

```gherkin
@important @automate
Scenario: Persist explainability trace
	Given a valid explainability payload and score id
	When the ExplainabilityStore write API is called
	Then the payload is persisted and `explainability_ref` is returned

@important @automate
Scenario: Retrieve explainability via /scores/{id}
	Given a persisted explainability_ref
	When GET /api/v1/scores/{id} is called
	Then the response contains explainability_payload matching persisted trace

@standard @automate-later
Scenario: Retention policy enforced
	Given traces older than retention period
	When retention job runs
	Then older traces are flagged or removed per policy

@important @automate
Scenario: Explainability models must be explainable
	Given a scoring model under test
	When model outputs are produced
	Then the pipeline records explainability traces and the model is not a black-box without explainability artifacts
```
