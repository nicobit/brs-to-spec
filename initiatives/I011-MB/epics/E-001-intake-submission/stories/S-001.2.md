# S-001.2 — Applicant Portal: Application Form UI

| Story ID | S-001.2 |
|---|---|
| Layers | Frontend |

Implement applicant portal form UI for submission and client-side validation.

| Layers | Integrations |

Implement Experian lookup integration for identity checks.

| Story Type | frontend-form |

## User Story

As an applicant I want to complete the online application form so that my application can be submitted for scoring and decisioning.

## Business Context

Client-side validation improves user experience and reduces invalid submissions. Server-side Experian lookup increases data quality for scoring.

AC Tags: [important] [automate]

```gherkin
@important @automate
Scenario: Happy path - Experian returns match
	Given an application with valid identity
	When the Experian adapter is called
	Then the identity result is persisted and status is "matched"

@important @automate
Scenario: No match - Experian returns no match
	Given an application with insufficient identity data
	When Experian returns no match
	Then the application is flagged for manual review and status is "identity_unverified"

@standard @automate-later
Scenario: Client-side validation blocks bad input
	Given an applicant submits invalid email and dob
	When the form is submitted
	Then the client shows validation errors and does not call the backend

@important @automate
Scenario: Experian adapter retry on transient error
	Given Experian returns a transient 5xx error
	When the adapter retries within backoff policy
	Then eventual success persists identity or an error is recorded for manual retry
```

*End of story.*
