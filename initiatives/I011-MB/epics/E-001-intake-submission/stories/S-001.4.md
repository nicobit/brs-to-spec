# S-001.4 — Status retrieval API and UI (/applications/status)

| Story ID | S-001.4 |
|---|---|
| Layers | Backend / Backend API / Frontend |

| Story Type | frontend-page |

## User Story

As an applicant I want to check the status of my application using ARN and DOB so I can see progress without contacting support.

## Business Context

Self-service status reduces support load and provides transparency (FR-005).

## Requirements Implemented

- FR-005

## Requirements Referenced

- FR-001

## In Scope

- Implement GET `/api/v1/applications/status?arn={}&dob={}` and a simple UI page to present status.

## Implementation Guidance

Authenticate queries minimally; rate-limit to prevent abuse. Use ARN + DOB matching per contract.

## Test Expectations

- Integration tests for API response and UI rendering

## Required Tests

- 1 integration test

AC Tags: [important] [automate]

```gherkin
@important @automate
Scenario: Status found
	Given an application exists with ARN X and DOB Y
	When GET /api/v1/applications/status is called with X and Y
	Then the API returns 200 and the current status

@standard @automate-later
Scenario: Status not found
	Given no application matches ARN and DOB
	When the API is called
	Then the API returns 404

@important @automate
Scenario: Invalid input returns 400
	Given an invalid ARN format
	When the API is called
	Then the API returns 400 with validation details

@standard @automate
Scenario: Authorization required for sensitive status
	Given a caller without necessary credentials
	When the API is called for a protected status
	Then the API returns 403
```

*End of story.*
