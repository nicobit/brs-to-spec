# S-001.6 — Integration: Experian / Email provider adapters

| Story ID | S-001.6 |
|---|---|
| Layers | Integration / Integrations |

| Story Type | generic |

## User Story

As an integration engineer I want adapters for Experian and the email provider so that identity checks and emails are abstracted behind a stable contract.

## Business Context

Adapters isolate third-party dependencies and enable testing and retries (FR-003, FR-004).

## Requirements Implemented

- FR-003

## Requirements Referenced

- FR-004

## In Scope

- Implement Experian and email provider adapters with retry/backoff and idempotency where applicable.

## Implementation Guidance

Follow adapter patterns and surface a consistent result object to calling services. Log failures for manual reconciliation.

## Test Expectations

- Adapter unit tests, integration tests mocking provider responses, contract tests for expected payloads.

## Required Tests

- 2 unit tests
- 1 integration test

## Dependency Contracts

| Contract | Purpose |
|---|---|
| external/experian-contract | Experian mapping and sample responses |
| epics/E-001-intake-submission/stories/S-001.2.agent.yaml | Applicant form contract |

AC Tags: [important] [automate]

```gherkin
@important @automate
Scenario: Experian success
	Given an application with sufficient identity data
	When the Experian adapter is called
	Then a matched identity result is returned

@important @automate
Scenario: Experian no match
	Given an application with insufficient identity data
	When the Experian adapter returns no match
	Then the adapter returns an explicit no-match result

@standard @automate
Scenario: Email provider send success
	Given a templated confirmation message
	When the email adapter sends the message
	Then the provider acknowledges delivery

@important @automate
Scenario: Email provider transient failure queued
	Given the email provider is temporarily unavailable
	When the adapter sends a message
	Then the message is enqueued for retry and an error is logged
```

*End of story.*
