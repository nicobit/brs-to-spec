# S-001.3 — Confirmation Email & ARN display

| Story ID | S-001.3 |
|---|---|
| Layers | Backend / Backend API |

| Story Type | event-consumer |

## User Story

As an applicant I want to receive a confirmation email and see my application ARN so I have proof of submission and a reference for enquiries.

## Business Context

Confirmation reduces inbound support and creates an auditable trail confirming submission (FR-004).

## Requirements Implemented

- FR-004

## Requirements Referenced

- FR-001

## In Scope

- Generate and send confirmation email containing ARN; surface ARN in UI response.

## Implementation Guidance

Use email provider adapter (see S-001.6). Ensure email content is templated and localized per epic guidelines.

## Test Expectations

- Integration test verifying email provider call and persisted ARN
- Unit tests for template rendering

## Required Tests

- 1 integration test
- 1 unit test

| epics/E-001-intake-submission/stories/S-001.1.agent.yaml | Submission API contract |
AC Tags: [important] [automate]
```gherkin
@important @automate
Scenario: Happy path - confirmation email sent
	Given an application submission completes successfully
	When the system sends a confirmation email
	Then the email provider receives a correctly templated message containing the ARN

@important @automate
Scenario: Email provider transient failure queued
	Given the email provider returns a transient error
	When the system enqueues the message for retry
	Then the message is retried per backoff and logged for manual follow-up

@standard @automate-later
Scenario: ARN returned in API response
	Given a successful submission
	When the API returns the response
	Then the response body contains the application ARN

@important @automate
Scenario: Email provider permanent failure - manual follow-up
	Given the email provider returns a permanent failure
	When the system records the failure
	Then an operator ticket is created and the ARN is recorded for outreach
```

*End of story.*
