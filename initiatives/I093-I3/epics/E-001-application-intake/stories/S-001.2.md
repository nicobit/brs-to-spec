
# S-001.2 — Assign ARN and send confirmation

| Field | Value |
|---|---|
| Layers | Backend, Integration |

Requirement Traceability:
- FR-003: Assign Application Reference Number
- FR-004: Submission confirmation email
- REQ-002, REQ-003

## Business Context

Backend must persist applications and issue ARNs reliably to avoid duplicate processing and to enable applicant status lookup and downstream scoring.

## User Story

As the system, I want to persist a submitted application and return a unique ARN so that applicants can reference and track their application.

## Description
Create backend endpoint to persist application, assign ARN, enqueue scoring, and trigger confirmation email.

## Implementation Guidance

Follow API surface in implementation contract. Ensure idempotency keys and unique ARN generation.

## Test Expectations

- Integration tests for ARN uniqueness and message enqueue
- Contract tests for email provider integration

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Happy path - backend assigns ARN
	Given a valid application payload
	When the backend persists the application
	Then it returns a unique ARN and emits ApplicationSubmitted event

Scenario: Email failure fallback
	Given the confirmation email provider is unavailable
	When the backend enqueues the email
	Then the system retries and records outbound email status for monitoring
```
