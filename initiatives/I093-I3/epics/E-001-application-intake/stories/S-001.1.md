
# S-001.1 — Build applicant intake form

| Field | Value |
|---|---|
| Layers | Frontend, Backend |

Requirement Traceability:
- FR-001: Online application intake fields
- FR-002: Inline validation before submission
- REQ-001

## Business Context

Applicants must be able to submit applications quickly and reliably; missing or invalid data causes manual rework and delays downstream scoring.

## User Story

As an applicant, I want to complete an online form so that I can apply for a loan and receive an ARN confirming receipt.

## Description
Implement the public intake form with inline validation for mandatory fields and client-side checks. On submit, POST to intake API and show ARN returned from backend.

## Implementation Guidance

Reference implementation contract for API and event contracts; use existing frontend starter components and shared validation library.

## Test Expectations

- Unit tests for validation rules
- E2E test for successful submission returning ARN

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Happy path - applicant submits valid application
	Given an applicant has completed all mandatory fields
	When they submit the intake form
	Then they receive a 200 response and an ARN is shown

Scenario: Validation - missing mandatory field
	Given an applicant omits a mandatory field
	When they attempt to submit
	Then the UI shows inline validation and the submission is blocked
```
