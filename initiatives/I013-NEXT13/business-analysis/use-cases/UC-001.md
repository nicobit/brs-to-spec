# UC-001 — Submit Application

## Metadata

| Field | Value |
|---|---|
| UC-ID | UC-001 |
| Title | Submit Application |
| Primary Actor | Applicant |
| Status | Draft |

## Preconditions

- Applicant has necessary identity and application data ready.

## Main Success Scenario

1. Applicant fills application form and submits.
2. System validates mandatory fields and returns inline errors if any (BR-001).
3. On successful validation the system assigns an ARN (BR-002) and persists the application in SUBMITTED state.
4. System emits submission event to start AI scoring pipeline (FR-006).
5. System sends confirmation email within 2 minutes (BR-003 / FR-004).

## Alternative Flows

- A1: Missing mandatory fields — form shows inline errors and submission is blocked (FR-002).
- A2: Experian lookup required by downstream steps — scoring may proceed after transient lookup (FR-009).

## Exception Paths

- E1: Notification delivery fails — retry per notification policy and surface transient error to operations if retries exhausted.

## Postconditions

- Application persisted with ARN and SUBMITTED state; submission event published.

## Business Rules Referenced

- BR-001, BR-002, BR-003
