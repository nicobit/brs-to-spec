# F-006.1 — Disbursement Trigger & Confirmation

| Field | Value |
|---|---|
| Layers | Integration, Backend, Infrastructure |
| Story ID | F-006.1 |

## Business Context

After cooling-off expiry and acceptance, the system must instruct Temenos T24 to disburse funds and handle confirmations or retries.

## User Story

As an Operations system, I want to send disbursement instructions to T24 so that funds are transferred to the applicant's account and the application state updates to DISBURSED.

## Acceptance Criteria (Gherkin)

```gherkin
@integration @happy
Scenario: Disbursement succeeded
  Given an accepted offer and cooling-off period elapsed
  When the disbursement instruction is sent to T24
  Then a confirmation is received and the application state is set to DISBURSED

@integration @negative
Scenario: Disbursement failure
  Given a disbursement instruction fails
  When the system does not receive confirmation
  Then the system retries once and raises an alert on repeated failure
```

## Linked Requirements

- REQ-010

## Implementation Guidance

- Use the Temenos T24 integration contract and idempotent transaction identifiers. Ensure disbursement instructions include ARN, account, sort code, reference and value date per REQ-010. Implement retry with alerting on repeated failure.

## Test Expectations

- Integration tests against T24 sandbox, contract tests validating instruction payloads, and e2e tests confirming application state transitions to DISBURSED.
