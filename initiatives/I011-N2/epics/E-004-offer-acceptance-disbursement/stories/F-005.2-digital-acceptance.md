# F-005.2 — Digital Acceptance via E-Signature

| Field | Value |
|---|---|
| Layers | Frontend, Integration, Backend |
| Story ID | F-005.2 |

## Business Context

Applicants accept offers via an e-signature gateway (DocuSign); acceptance must be logged with timestamp and IP and trigger cooling-off tracking.

## User Story

As an Applicant, I want to e-sign the offer so that my acceptance is legally captured and the process continues to disbursement.

## Acceptance Criteria (Gherkin)

```gherkin
@integration @happy
Scenario: Applicant accepts offer via DocuSign
  Given a generated offer with a DocuSign link
  When the applicant signs via DocuSign
  Then acceptance is recorded with timestamp and IP and the cooling-off timer starts

@integration @negative
Scenario: DocuSign callback failure
  Given a signed offer but DocuSign callback fails
  When the system does not receive confirmation
  Then signature acceptance is retried and an operational alert is raised if undelivered
```

## Linked Requirements

- REQ-009

## Implementation Guidance

- Reference DocuSign integration contract for callback and webhook handling; store acceptance metadata in audit store with encryption.

## Test Expectations

- Integration tests to simulate DocuSign signing flow, callback, and failure/retry behavior.
