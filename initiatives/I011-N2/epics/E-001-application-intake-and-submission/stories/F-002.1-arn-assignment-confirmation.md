## User Story

As the System, upon successful application submission I want to assign a unique ARN and send an email confirmation so the applicant receives proof of submission and an identifier for status checks.

---

## Business Context

Assigning an ARN and confirming by email allows applicants to track their application and supports subsequent customer service interactions.

---

| ID | Requirement |

## Implementation Guidance

- **Entity:** ApplicationReference
- **API:** Response of `POST /api/applications` includes `arn` field; background job or synchronous email via Notification Service
- **Events:** `application.confirmation.sent` (integration telemetry)
- **Rules:** ARN format `ARN-{YYYY}{6-digit}` or UUID as decided by implementation; email must contain ARN and expected decision timeline

---

## Acceptance Criteria

### AC-001 — ARN returned on successful submission `[e2e]`

```gherkin
Scenario: ARN assigned and returned
  Given a valid application is submitted
  When the backend persists the application
  Then the response includes a unique ARN
```

### AC-002 — Email confirmation sent within SLA `[integration]`

```gherkin
Scenario: Email confirmation sent with ARN
  Given an application is accepted and persisted
  When the notification is queued
  Then the Notification Service sends an email containing the ARN within 2 minutes
```

### AC-003 — Applicant can retrieve status with ARN `[integration]`

```gherkin
Scenario: Status retrieval via ARN
  Given an applicant has an ARN and DOB
  When they call `GET /api/applications/status?arn={arn}&dob={dob}`
  Then the system returns application status and minimal details without requiring registration
```
