## User Story

As an Applicant, I want to complete an online application form with inline validation so that I can submit a valid application and receive an ARN.

---

## Business Context

The application form is the primary customer touchpoint; high quality validation reduces invalid submissions, support costs, and accelerates downstream processing.

## Implementation Guidance

- **Entity:** LoanApplication
- **API:** `POST /api/applications` (accepts application payload, returns ARN)
- **Status:** `SUBMITTED` on successful validation and persistence
- **Events:** `application.submitted` containing ARN and minimal applicant metadata
- **Rules:** mandatory fields: name, DOB, NI, employment, income, loan amount, purpose, term; server-side validation must match client constraints

---

## Acceptance Criteria

### AC-001 — Submit valid application `[e2e]`

```gherkin
Scenario: Successful submission of valid application
  Given an applicant has filled all mandatory fields with valid values
  When they submit the application
  Then the system returns HTTP 201 with a unique ARN
  And the application is persisted with status SUBMITTED
```

### AC-002 — Prevent submission with missing mandatory field `[unit]`

```gherkin
Scenario: Missing mandatory field prevents submission
  Given an applicant left the DOB field empty
  When they attempt to submit the application
  Then the client shows an inline validation error for DOB
  And the backend rejects the submission with HTTP 400 and error details
```

### AC-003 — Validation rules enforced server-side `[integration]`

```gherkin
Scenario: Server enforces same validation rules as client
  Given a crafted request bypassing client-side checks
  When the request is POSTed to `/api/applications`
  Then the server validates mandatory fields and returns HTTP 400 for invalid payloads
```
