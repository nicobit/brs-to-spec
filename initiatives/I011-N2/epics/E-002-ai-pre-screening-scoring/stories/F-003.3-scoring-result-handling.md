# F-003.3 — Scoring Result Handling & Audit

| Field | Value |
|---|---|
| Layers | Backend, Infrastructure |
| Story ID | F-003.3 |

## Business Context

Scoring outcomes must be durable, auditable, and drive downstream decisions (offers, referrals). All state transitions must be recorded immutably.

## Linked Requirements

- REQ-011 — Immutable Audit Log
- REQ-013 — Encryption and Data Residency

## User Story

As an Ops team, I want scoring results to be persisted immutably so that compliance and reconciliation can be performed reliably.

## Implementation Guidance

- Write scoring results and recommendation labels to the immutable audit store (append-only Cosmos DB container) with AES-256 encryption and UK-region tenancy.
- Emit structured observability events for key milestones (scoring_started, scoring_completed, experian_failure).

## Acceptance Criteria (Gherkin)

```gherkin
@e2e @happy
Scenario: Scoring result persisted to immutable audit log
	Given a scoring result is produced for a valid ARN
	When the result is persisted to the audit store
	Then an immutable audit entry shall exist recording ARN, timestamp, previous state, new state, scoring payload snapshot, and correlation ids

@e2e @negative
Scenario: Audit store write failure
	Given a scoring result is produced
	When writing to the audit store fails
	Then the system shall retry once and then raise an operational alert while preserving a local secured snapshot for manual reconciliation
```

## Test Expectations

- End-to-end tests verify audit entry creation, encryption metadata, and event emission to the metrics pipeline.

## Dependencies

- Cosmos DB append-only container, key vault access, observability pipeline.

## Open Questions

- Retention and archival policy for audit entries (storage cost vs compliance).
