# F-003.2 — Experian Integration & Fallback

| Field | Value |
|---|---|
| Layers | Integration, Backend, Infrastructure |
| Story ID | F-003.2 |

## Business Context

Accurate scoring requires credit bureau data. The system must retrieve an Experian credit report and surface failures as safe fallbacks to underwriter review.

## Linked Requirements

- REQ-006 — Experian Integration for Credit Reports
- REQ-007 — AML and KYC Screening (integration dependency)

## User Story

As a Scoring Service, I want reliable access to Experian credit reports so that the scoring model has the required inputs to produce accurate recommendations; if Experian is unavailable, applications must be safely routed for human review.

## Implementation Guidance

- Implement a dedicated Experian integration component with timeout (e.g., 30s) and circuit-breaker.
- On success, attach credit report data to the scoring payload; on failure or timeout, mark the application for `REFER_TO_UNDERWRITER` and include failure reason in audit.

## Acceptance Criteria (Gherkin)

```gherkin
@integration @happy
Scenario: Experian returns credit report within SLA
	Given the Scoring Service requests a credit report for a valid ARN
	When the Experian API returns a report within 30 seconds
	Then the report is included in the scoring payload and scoring proceeds

@integration @negative
Scenario: Experian times out or fails
	Given the Scoring Service requests a credit report
	When Experian is unavailable or does not respond within 30 seconds
	Then the application is routed to REFER_TO_UNDERWRITER and the reason is recorded in audit
```
