# F-004.3 — Compliance Hold Routing & Notifications

| Field | Value |
|---|---|
| Layers | Backend, Integration, Infrastructure, Frontend |
| Story ID | F-004.3 |

## Business Context

When AML/KYC checks fail, applicants must be routed to a compliance hold and appropriate teams must be notified to perform manual review.

## User Story

As a Compliance Officer, I want failed checks to create a compliance hold with evidence so that I can triage and resolve cases efficiently.

## Implementation Guidance

- On detection of AML/KYC failure, set application state to `COMPLIANCE_HOLD`, attach evidence to the audit entry, and send structured notification to compliance queue and applicant.
- Include business hours-aware escalation for unactioned holds (REQ-015).

## Acceptance Criteria (Gherkin)

```gherkin
@integration @happy
Scenario: Compliance hold created and notifications sent
  Given an application fails AML screening
  When the system creates a compliance hold
  Then a compliance notification is sent and the applicant is informed

@integration @negative
Scenario: Notification failure
  Given a compliance hold is created
  When notification delivery fails
  Then the system retries and raises an operational alert if undelivered
```

## Test Expectations

- Integration tests for hold creation, notification delivery, and escalation.

## Dependencies

- Notification service, compliance inbox, business hours config.

## Open Questions

- Escalation contacts and business hours configuration specifics.
