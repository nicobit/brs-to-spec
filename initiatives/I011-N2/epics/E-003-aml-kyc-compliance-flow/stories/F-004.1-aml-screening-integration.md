# F-004.1 — AML Screening Integration

| Field | Value |
|---|---|
| Layers | Integration, Backend |
| Story ID | F-004.1 |

## Business Context

Automated AML screening reduces regulatory risk by detecting sanctioned entities quickly and routing them out of offer flows.

## User Story

As a Compliance system, I want submitted applicants screened against the HM Treasury sanctions list so that matched records are prevented from progressing to offers.

## Implementation Guidance

- Integrate with the HM Treasury sanctions API with a sub-60s SLA and circuit-breaker.
- Normalize identity fields (name, DOB, NI) before matching; record matching confidence and evidence in the audit store.

## Acceptance Criteria (Gherkin)

```gherkin
@integration @happy
Scenario: AML screening passes
  Given an application with valid identity data
  When AML screening runs against HM Treasury list
  Then no match is found and the application proceeds

@integration @negative
Scenario: AML screening detects sanctioned party
  Given an application whose identity matches a sanctions record
  When AML screening completes
  Then the application is routed to COMPLIANCE_HOLD and compliance is notified
```

## Test Expectations

- Integration tests with sanctioned and non-sanctioned test vectors.

## Dependencies

- HM Treasury sanctions API access and credentials.
