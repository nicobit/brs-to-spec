# Wave 3 Enhancement Backlog

This backlog translates the Wave 3 roadmap into concrete enhancement items that extend the framework from strong context mechanics into a more mature, teachable, and continuously improving context-driven system.

Wave 3 focuses on usability, consistency, and learning from downstream experience.

## Wave 3 objective

Make the framework easier for different consumers to use, stronger at pattern transfer, and progressively smarter through structured feedback from real implementation outcomes.

## Backlog item 3.1: Create role-specific context views

### Objective

Project the same source-of-truth context into role-appropriate views for different consumers without creating competing sources of truth.

### Problem being solved

The framework already identifies artifact consumers well, but those consumers still often need to reinterpret the same context manually.

That can lead to:

- overexposure to irrelevant detail
- underexposure to important role-specific concerns
- inconsistent use of the same initiative context across roles

### Candidate framework additions

- role-specific context-view definitions
- rules for which artifact sections should be elevated by role
- guidance for what should be omitted or downplayed by role
- a distinction between source-of-truth artifacts and consumer-specific projections

### Success criteria

- each major consumer type has a clearer context shape
- the same initiative context becomes easier to consume without duplication
- role-based AI or human workflows become more consistent

### Priority

Medium

## Backlog item 3.2: Add approved examples as first-class context objects

### Objective

Treat curated examples as a formal part of framework context so that downstream AI consumers can learn from strong patterns, not only from abstract rules.

### Problem being solved

Instructions and templates help, but AI agents often perform better when they also receive examples of high-quality outputs and common failure patterns.

Without this, the framework may remain:

- rule-rich but pattern-light
- clear in principle but less consistent in output style and quality

### Candidate framework additions

- an example-library concept
- rules for when examples should be included in packaging
- guidance for strong-versus-weak examples
- distinction between illustrative examples and governing artifacts

### Success criteria

- examples improve consistency of generated artifacts
- users can reuse proven patterns without copying whole prior deliverables blindly
- AI agents receive better pattern guidance for non-trivial outputs

### Priority

Medium

## Backlog item 3.3: Create a feedback loop from implementation outcomes into framework refinement

### Objective

Use recurring downstream implementation and review outcomes to improve upstream framework guidance over time.

### Problem being solved

Without a structured learning loop, repeated issues remain local and the framework does not systematically improve from real delivery experience.

Typical missed learning sources include:

- recurring code review findings
- repeated ambiguity in handoff tasks
- common readiness misses
- repeated brownfield surprises

### Candidate framework additions

- a framework feedback model
- categories for actionable downstream findings
- rules for when a finding should update templates, readiness guidance, architecture rules, or packaging guidance
- a distinction between one-off issues and repeat-pattern issues

### Success criteria

- repeated downstream problems become visible as framework improvement candidates
- the framework evolves from delivery evidence, not only design intent
- avoidable failure patterns decrease over time

### Priority

Medium-High

## Suggested Wave 3 sequence

Recommended order:

1. `3.1` role-specific context views
2. `3.2` approved examples as first-class context objects
3. `3.3` feedback loop from implementation outcomes into framework refinement

Reasoning:

- role-specific views improve immediate usability once Waves 1 and 2 define the underlying context system
- examples improve output consistency once those views exist
- the feedback loop is most valuable after the framework has enough operational shape to learn from repeated usage patterns

## Suggested acceptance view for Wave 3

Wave 3 should be considered successful when the framework can answer these questions clearly:

- how should this same context be presented differently to different consumers?
- what proven examples should guide this kind of work?
- how do repeated downstream issues improve the framework instead of repeating forever?

If those questions can be answered consistently, the framework will have moved from structured context delivery toward a genuinely adaptive context-driven operating model.
