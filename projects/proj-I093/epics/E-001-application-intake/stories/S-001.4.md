
# S-001.4 — Auto-decline notifications and cooling-off

| Field | Value |
|---|---|
| Layers | Integration, Infrastructure |

Requirement Traceability:
- FR-011: Auto-decline notifications and cooling-off
- REQ-002, REQ-003

## Business Context
Applicants must receive timely decline notifications; cooling-off prevents repeated reapplications and reduces abuse.

## User Story

As the system, I want to notify applicants of auto-declines and record a cooling-off window so that reapplications are controlled.

## Description
Implement notification publishing and cooling-off enforcement for auto-declined applications.

## Implementation Guidance

Use the notification service and a WORM flag for cooling-off enforcement; record events immutably.

## Test Expectations

- Integration tests for notification delivery and cooling-off enforcement

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: Auto-decline notification
  Given an application is auto-declined
  When the system processes the decline
  Then the applicant receives a notification within 5 minutes and the cooling-off window is recorded

Scenario: Cooling-off prevention
  Given an applicant is in cooling-off window
  When they attempt to reapply
  Then the system rejects the submission with appropriate error
```
