# Engineering Ready Checklist

Do not proceed to OpenSpec tasks or Copilot implementation until this is complete.

## Architecture

- [ ] Technical spec follows existing architecture.
- [ ] Impacted components are identified.
- [ ] No unnecessary new services/frameworks are introduced.
- [ ] API/event/data impact is clear.
- [ ] Integration impact is clear.
- [ ] Backward compatibility is considered.

## Security / audit

- [ ] Authorization rules are clear.
- [ ] Sensitive data handling is clear.
- [ ] Audit events are defined where needed.
- [ ] Logging expectations are clear.

## Testing

- [ ] BDD scenarios exist for key behavior.
- [ ] Test strategy is clear.
- [ ] Test plan exists if needed.
- [ ] Automation candidates are identified.
- [ ] Regression impact is understood.

## OpenSpec readiness

- [ ] Proposal is clear.
- [ ] Design is clear.
- [ ] Tasks are small.
- [ ] Each task has tests and Definition of Done.

## BRS and architecture alignment

- [ ] `brs-architecture-alignment.md` reviewed if available.
- [ ] Architecture constraints are reflected in the technical spec.
- [ ] Open architecture decisions have owners.
- [ ] BRS/architecture contradictions are resolved or explicitly deferred.
