# Product Owner Simplified Intake

The Product Owner should not be forced to manage many low-level documents.

For large initiatives, the PO should provide the raw BRS and review a single consolidated output first.

## PO-facing output

```text
business-intake/business-intake-summary.md
```

This output includes:
- executive summary,
- objectives,
- scope,
- out of scope,
- high-level requirements,
- business capabilities,
- gaps/questions,
- risks,
- assumptions,
- initial delivery concerns.

## PO should review

- business meaning,
- scope,
- priorities,
- missing requirements,
- wrong interpretations,
- business capability grouping,
- major open questions.

## PO should not manually manage

- low-level module specs,
- OpenSpec tasks,
- implementation checklists,
- API contracts,
- data model details,
- unit test tasks.
