# Coding Constraints

Use this policy when preparing implementation handoff artifacts for coding
agents.

Rules:

- keep changes within the approved architecture boundaries
- do not imply permission to redesign the solution during implementation
- call out likely impacted files, modules, services, and interfaces explicitly
- distinguish binding constraints from suggestions
- make test expectations executable, not aspirational
- include non-functional constraints such as performance, security, audit, and
  rollback expectations when they apply
- identify areas that must not be changed without a fresh architecture decision
